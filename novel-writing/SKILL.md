# 长篇小说分章写作工作流

## 核心原则

长篇写作的最大风险不是文笔，而是**设定漂移**：人物前后矛盾、伏笔忘记回收、时间线错乱。本 skill 用三个文件锁住一致性，每次写作会话都必须走完整流程，不许跳步。

## 项目文件结构（首次写作时在当前工作区创建）

```
<小说项目目录>/
├── outline.md        # 大纲：立意、人物、结构、分章 beats、意象/伏笔清单
├── handoff.md        # 交接文档：当前进度快照（见 references/templates.md）
└── chapters/
    ├── 第01章_章名.md   # 每章正文，文件头带元信息块
    └── ...
```

## 每次写作会话的固定流程

### 第一步：读取与校对（动笔前，强制）

1. 读 `outline.md` 全文 + `handoff.md` 全文 + **最近两章正文**；更早章节只读 `handoff.md` 里的章节摘要。
2. 对用户本次的要求做**大纲校对（proofreading）**，逐项检查：
   - 人设一致性：性格、口癖、身世是否与 outline.md 冲突
   - 时间线：本章事件与前后章的时间、季节、天数是否咬合
   - 伏笔：本章是否要埋/收某条伏笔（对照 outline 的伏笔清单）；已埋伏笔有没有被遗忘
   - 视角与人称：是否遵守既定叙述纪律（如"某角色不给正脸"）
   - 文风：是否叠加了文风 skill，其笔法规则是什么
3. 发现冲突时**先向用户报告冲突点并给出修法，等确认后再动笔**；无冲突则用两三句话陈述校对结论再动笔。

### 第二步：写作

按既定文风与大纲写本章。篇幅、钩子、章末留悬念的要求以 outline.md 为准。

#### 章节独特性纪律（反模板化，强制）

长篇连载最常见的失败是每章写成同一个模子：同样的开场方式、同样的"日常→感慨→钩子"曲线、同样的意象反复出现。动笔前与写完后各做一次反重复检查：

1. **开场方式轮换**：记录最近三章的开场类型（景物定场 / 对话切入 / 动作进行中 / 倒叙跳入 / 他人视角）。本章开场不得与上一章同类型，连续三章不得同类型。
2. **情绪曲线差异化**：每章在 `handoff.md` 标注主导情绪（甜/悬/痛/暖/释）。相邻两章不得同情绪同强度——甜章之后要么更甜出新高，要么转入不安，不许原地再甜一次。
3. **意象预算制**：核心意象（如雪、信物、某种食物）按 outline 伏笔清单的"埋/转/收"节点使用，节点之外不许顺手再用——同一意象每多出现一次，它的重量就稀释一分。
4. **句式指纹检查**：写完通读一遍，若发现与前几章雷同的标志性句式（同样的结尾句式、同样的转折词开段），改掉其中至少一半。
5. **每章一个"只有这章有"的东西**：一个独有的场景、物件、对话梗或视角小实验，写进章节元信息的"独特点"字段。想不出来，说明这章还没写好。

写完按 1–4 自检并在章节元信息里记录"独特点"与"主导情绪"；两项缺失视为未完成。

### 第三步：审校（写完后，先审后归档，强制）

调用 `novel-proofreading` skill 对刚写完的本章做多遍审校（大纲对照→章内逻辑→看客模拟），问题清单修复完毕后才算成稿。

### 第四步：归档与交接（审校通过后，强制）

1. 正文存入 `chapters/第NN章_章名.md`，文件头写元信息块（章节号、章名、本文字数、时间线位置、本章埋/收的伏笔）。
2. 更新 `handoff.md`：进度、本章摘要（3-5 句）、未收伏笔清单的增删、人物状态变化、下一步该写哪章。
3. 若本章写作中临时改动了设定（新人物、新细节），**反向同步到 outline.md**，保持大纲为唯一事实源。
4. 向用户交付时报告：审校问题清单与修复情况、本章字数、伏笔变动、handoff 已更新。

## 模板

三个文件的完整模板（outline.md / handoff.md / 章节元信息块）见 [references/templates.md](references/templates.md)。首次建项目时按模板生成。

## 禁忌

- 禁止跳过第一步直接动笔，哪怕用户催更——校对最长不超过一次回复的篇幅
- 禁止只更新 handoff 不回同步 outline
- 禁止在 handoff 里抄写整章正文，只写摘要
- 章节文件一经用户确认定稿，后续修改须走"修订"流程并在 handoff 记录改动
